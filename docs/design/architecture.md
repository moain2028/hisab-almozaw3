## الطبقات

| الطبقة | الملفات | المسؤولية | تعتمد على |
|---|---|---|---|
| النماذج | `models/models.dart` | بيانات غير قابلة للتعديل للحركات، و`toMap/fromMap` متسامح مع القيم الناقصة | لا شيء |
| المحاسبة | `data/ledger.dart` | دوال صافية: `shopDay`، `shopBalance`، `buildReport`، `dayStock` | النماذج |
| الفهرس | `data/ledger_index.dart` | `AccountIndex`: ترتيب + prefix sums + بحث ثنائي | النماذج |
| المخزن | `data/store.dart` | الحالة، والتخزين، والإبطال الانتقائي، والتصدير والاستيراد | كل ما سبق + Hive |
| النسخ | `data/backup_service.dart` | الملفات، والضغط، والتحقق، والتدوير | المخزن |
| الواجهة | `screens/`، `ui/` | العرض والإدخال فقط، بدون منطق محاسبي | المخزن |

**القاعدة:** لا توجد أي عملية حسابية للأرصدة داخل الشاشات. كل الأرقام تأتي من `Store`، والمخزن يعتمد على `ledger`. لذلك تكفي اختبارات `ledger` و `store` لضمان صحة كل ما يُعرض.

## نموذج البيانات

| الكيان | أهم الحقول | ملاحظات |
|---|---|---|
| `Shop` | `openingBalance`، `routeOrder`، `archived` | الدين السابق قبل البرنامج يُكتب مرة واحدة |
| `Product` | `sellPrice`، `costPrice`، `active` | الصنف المستخدم لا يُحذف بل يُخفى |
| `ShopTx` | `type ∈ {delivery, returned, payment, discount}`، `day`، `lines` | `amount` يُحسب مرة واحدة عند الإنشاء |
| `TxLine` | `qty` (عشري)، `price`، `cost` | **السعر والتكلفة يُنسخان وقت العملية**: تغيير سعر الصنف لا يغيّر التاريخ |
| `TraderTx` | `type ∈ {pickup, returned, payment}` | تُسعَّر بسعر الشراء |
| `Expense` | `category`، `amount` | |

- **اليوم التجاري** نص `yyyy-MM-dd`. هو قابل للمقارنة الأبجدية، وثابت لا يتأثر بالمنطقة الزمنية، ومفتاح طبيعي للفهارس.
- **المبالغ أعداد صحيحة** (بدون كسور عشرية للعملة)، لتجنب أخطاء الفاصلة العائمة في المجاميع.

## دورة التعديل

1. الشاشة تستدعي `store.saveShopTx(tx)`.
2. المخزن يحدّث الـ Map والفهارس التزايدية، ويُبطل **فهرس تلك البقالة فقط** وكاش الملخصات.
3. `notifyListeners()`، فتعيد الواجهة البناء. الحساب هنا O(log n) من الفهرس.
4. الكتابة على Hive تتم بعد الإشعار، حتى تستجيب الواجهة فوراً ولا تنتظر القرص.
5. `onDataChanged`، فيبدأ مؤقت النسخ التلقائي (8 ثوانٍ من الهدوء).

## دورة حياة التطبيق

| الحدث | الإجراء |
|---|---|
| الإقلاع | فتح الصناديق بالتوازي (`Future.wait`)، والتحميل، ثم أول إطار، ثم نسخة تلقائية إن وُجدت تغييرات غير منسوخة |
| `resumed` | إن عبر منتصف الليل والتطبيق مفتوح: الانتقال لليوم الجديد |
| `paused` | `flush()` لكل الصناديق، وتنفيذ أي نسخة معلّقة فوراً |
