# ADR 0011 — لوحة الأجهزة والتحكم على الدومين (مقترح، لم يُنفَّذ)

- الحالة: **مقترح** — ينتظر من المستخدم: Cloudflare **API Token** (Pages: Edit، Workers: Edit، D1/KV: Edit، DNS: Edit على alabbasi.uk) + **Account ID**.

## المطلوب (كلام المستخدم)
صفحة على دوميني، بكلمة سر، تعرض الأجهزة المثبّت عليها التطبيق، وأستطيع إغلاق/فتح (true/false) جهازاً أو الكل، «بدون Back-end، فقط من المستودع».

## الحقيقة التقنية (بصراحة)
1. **«بدون أي خادم» مستحيل جزئياً:** ليظهر عندك الجهاز يجب أن **يرسل** التطبيق شيئاً لمكان ما. مستودع GitHub لا يستقبل كتابة من الجوالات إلا بمفتاح كتابة داخل التطبيق ⇒ أي شخص يفك الـ APK يأخذ المفتاح ويتحكم بمستودعك. **مرفوض أمنياً.**
2. **الحل الأصح بلا خادم تديره أنت:** Cloudflare (مجاني ضمن حدود كبيرة) — ليس «Back-end» تصونه:
   - **Worker** صغير على `api.alabbasi.uk` يستقبل «نبضة» من التطبيق: `{deviceId عشوائي، الطراز، الإصدار، آخر ظهور}` ويخزنها في **D1/KV**.
   - **Pages** على `admin.alabbasi.uk`: لوحة عربية بقائمة الأجهزة + مفتاح إغلاق لكل جهاز وللكل.
   - الحماية: **Cloudflare Access** (تسجيل دخول ببريدك + رمز لمرة واحدة) — أقوى من كلمة سر في الصفحة.
   - التطبيق يقرأ حالته `active` من الـ Worker، ويبقى `license.json` في المستودع كمفتاح طوارئ للكل (يعمل كما اليوم).
   - النشر تلقائي من GitHub (مستودع خاص) عند كل push.
3. **الخصوصية:** لا اسم ولا رقم ولا موقع — معرّف عشوائي يولّده التطبيق + اسم يكتبه المستخدم اختيارياً. يجب ذكر ذلك في صفحة الخصوصية.

## الخطة عند وصول الـ Token
1. مستودع خاص `hisab-console`: Worker + Pages + مخطط D1.
2. نطاقان فرعيان جديدان فقط (`api.` و `admin.`) — لا مساس ببقية صفحات الدومين.
3. التطبيق 2.5.0: نبضة عند الفتح (مرة كل 6 ساعات) + قراءة حالة الجهاز. بلا إنترنت = آخر حالة معروفة (كما الآن).
4. اختبارات: Worker (وحدة) + تكامل التطبيق مع خادم وهمي.
