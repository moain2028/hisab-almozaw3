# 0001 — Hive + كل البيانات في الذاكرة
## السياق والمشكلة
المشروع الأصلي استخدم sqflite (لا يعمل على الويب، ويحتاج استعلامات SQL لكل شاشة). البيانات صغيرة نسبياً (موزّع واحد، عشرات البقالات، آلاف الحركات سنوياً)، والمستخدم يحتاج استجابة فورية.
## الخيارات
1. sqflite + استعلامات لكل شاشة.
2. Isar / Drift (توليد كود، تعقيد أكبر).
3. **Hive (key-value) + تحميل كامل للذاكرة + فهارس في الذاكرة.**
## القرار
الخيار 3، لأنه مثبّت في البيئة ويعمل على أندرويد والويب ولا يحتاج توليد كود. القراءة من الذاكرة فورية، والكتابة على القرص تتم بعد إشعار الواجهة.
## العواقب
- ✔ لا انتظار للقرص في أي شاشة؛ كود بسيط؛ يعمل على الويب للمعاينة.
- ✔ Hive سجل append-only يتحمل الانقطاع.
- ✘ الذاكرة تنمو خطياً (~15–20MB لسنتين). الحل عند الحاجة: أرشفة سنوية (STATUS M7).
- ✘ لا استعلامات معقدة، لكنها غير مطلوبة لأن الفهارس تغطي كل الشاشات.
